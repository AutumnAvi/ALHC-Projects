Latest phase: Integrations — two rule actions, **Send Slack message** (`send_slack`, Slack incoming webhook) and **Call webhook** (`call_webhook`, outbound HTTPS JSON with an optional shared-secret header), delivered like email: the rule runner queues `integration_outbox` rows and the app drains them with the service role (`src/lib/integrations.ts`, cron + after-action); the database never makes HTTP calls (see “Integrations model” in AGENTS.md). Webhook URLs and secrets live in `project_integrations` (Settings → Integrations, Admin+, redacted `get_project_integrations` / `set_project_integration`) and `integration_secrets` (moved out of `rules.actions` by a trigger); none of the three tables is readable by clients, and stories / run logs / toasts only show the redacted hint (host + last 4). Outbound URLs are HTTPS-only. Previous phase: Portfolios and reporting (`portfolio_members` roles; portfolio membership never grants project access). Project data stays gated by `project_members` roles (Teams & permissions); the email allowlist remains the outer sign-in gate.
