Latest phase: Asana importer — Settings → Import (Admin+) takes Asana project JSON and/or CSV exports uploaded to the private `imports` Storage bucket, parses them server-side (`src/lib/asana-import.ts`, never the Asana API, no Asana tokens), shows a dry-run preview (counts, already-imported, unmatched people), then sends idempotent batches to `rpc("import_batch")` (`previewAsanaImport` / `runAsanaImport` in `actions.ts`). External gids are tracked in `import_external_ids` so re-imports never duplicate or overwrite; runs in `import_runs`; attachments become name + link rows in `task_attachment_links`. While a batch runs (`alhc.import_run_id`), rules don't fire, nobody is notified, only a tagged `created` story is written, and any imported rule lands disabled (`rules_03_import_disabled`). See “Asana import model” in AGENTS.md. Previous phase: Redesign — visual/UX polish only: chrome tokens and `btn-*` / `control` / `chip` utilities in `globals.css`, shared `PageHeader` / `EmptyState` / skeletons in `src/components/ui.tsx`, `view-chrome.tsx`, `pane-styles.ts` (see “Design system” in AGENTS.md). Earlier: Integrations (`send_slack` / `call_webhook` via `integration_outbox`; the database never makes HTTP calls), Portfolios and reporting (portfolio membership never grants project access). Project data stays gated by `project_members` roles (Teams & permissions); the email allowlist remains the outer sign-in gate.
