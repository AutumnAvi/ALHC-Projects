@AGENTS.md

Latest phase: Templates — one copy engine in SQL (`project_snapshot` → `instantiate_project_snapshot`, both internal SECURITY DEFINER) behind project templates (`rpc("save_project_as_template")` Admin+, optional replace; `rpc("create_project_from_template")` with a start date — task dates are day offsets), `rpc("duplicate_project")` (Editor+; tasks / assignees / dates / rules / forms / members options), and per-project `task_templates` used from quick-add (`create_task_from_template`, SECURITY INVOKER, a normal task creation). While a copy runs, `alhc.copy_id` (`copy_context_id()`) mutes `fire_rules` / `notify_with` / `add_story` (their import checks unchanged) and forces every inserted rule disabled; each copy writes one `project_stories` row. Workspace Templates gallery at `/templates`; seeded **Creative Requests** example. See “Templates model” in AGENTS.md. Previous phase: Bulk edit and shortcuts — multi-select in List and My Tasks (checkbox, Shift range, ⌘/Ctrl toggle) with a bulk bar backed by one SECURITY INVOKER RPC, `rpc("bulk_update_tasks")` (≤ 200 tasks, partial apply: each task in its own subtransaction, skipped ones come back with title + reason; stories, inbox items, and rules fire per task as for single edits). List drag-and-drop reorders tasks (manual sort + section grouping) and sections through `place_task` / `place_section`, which take midpoints and reindex a section (`reindex_task_order` / `reindex_section_order`) when the gap gets too small. Keyboard shortcuts live in `src/components/shortcuts/` and never fire while typing. See “Bulk edit and shortcuts model” in AGENTS.md. Before that: Asana importer — Settings → Import (Admin+) takes Asana project JSON and/or CSV exports uploaded to the private `imports` Storage bucket, parses them server-side (`src/lib/asana-import.ts`, never the Asana API, no Asana tokens), shows a dry-run preview, then sends idempotent batches to `rpc("import_batch")`; while a batch runs (`alhc.import_run_id`), rules don't fire, nobody is notified, and imported rules land disabled (see “Asana import model” in AGENTS.md). Earlier: Redesign — visual/UX polish only: chrome tokens and `btn-*` / `control` / `chip` utilities in `globals.css`, shared `PageHeader` / `EmptyState` / skeletons in `src/components/ui.tsx`, `view-chrome.tsx`, `pane-styles.ts` (see “Design system” in AGENTS.md). Before that: Integrations (`send_slack` / `call_webhook` via `integration_outbox`; the database never makes HTTP calls), Portfolios and reporting (portfolio membership never grants project access). Project data stays gated by `project_members` roles (Teams & permissions); the email allowlist remains the outer sign-in gate.
